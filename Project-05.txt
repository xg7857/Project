# 과제 05: 순차 탐색과 이진 탐색 트리 탐색의 비교

## 1. 실행 방법

```
gcc search_compare.c -o search_compare
./search_compare
```

실행할 때마다 난수가 달라지므로 결과 수치도 매번 달라집니다. 아래는 한 번 실행한 결과입니다.

## 2. 비교 횟수 기준

- 순차 탐색: 배열 원소와 탐색 대상을 비교할 때마다 1회
- BST 탐색/삽입: 방문한 노드와 비교할 때마다 1회

## 3. 실행 결과

| 항목 | 순차 탐색 | BST |
|---|---|---|
| 탐색 횟수 | 50 (성공 2, 실패 48) | 50 (성공 2, 실패 48) |
| 총 비교 횟수 | 4,857 | 460 |
| 평균 비교 횟수 | 97.14 | 9.20 |
| 생성 비용 | 0 (저장만 함) | 674 |
| 생성 + 탐색 총 비교 | 4,857 | 1,134 |

- BST 높이: 14

## 4. 분석

### 4.1 탐색 성능 차이

순차 탐색은 실패하면 항상 100개를 모두 비교하므로 평균이 100에 가깝게 나왔습니다(97.14). 탐색 대상이 0~1,000 범위에서 생성되고 저장된 값은 100개뿐이라 대부분(48/50)이 실패였기 때문입니다.

BST는 탐색 한 번에 루트에서 리프 방향으로 한 경로만 내려가므로, 비교 횟수가 트리의 높이를 넘지 않습니다. 이번 트리의 높이는 14였고 평균 비교 횟수는 9.20이었습니다. 평균적으로 순차 탐색보다 약 10.6배 적게 비교했습니다. 데이터가 n개일 때 순차 탐색은 O(n), 균형이 맞는 BST는 O(log n)이라는 이론과 일치합니다.

### 4.2 BST 생성 비용을 고려한 분석

배열은 순서대로 저장하면 되지만 BST는 삽입할 때마다 위치를 찾느라 비교가 필요해서, 100개를 넣는 데 674회가 들었습니다. 생성 비용까지 합치면 BST는 1,134회, 순차 탐색은 4,857회로, 여전히 BST가 약 4.3배 적습니다.

탐색 한 번당 BST가 아끼는 비교는 약 87.9회(97.14 − 9.20)입니다. 생성 비용 674회를 만회하려면 약 7.7회, 즉 8번 정도만 탐색하면 됩니다. 따라서 이번처럼 50번 탐색하는 경우는 BST가 확실히 유리하고, 탐색을 한두 번만 하고 끝나는 경우에는 생성 비용 때문에 순차 탐색이 더 나을 수 있습니다.

### 4.3 트리 구조에 따른 성능 변화

BST의 탐색 성능은 트리 모양에 좌우됩니다.

- 균형에 가까운 경우: 노드 100개의 최소 높이는 7입니다. 이 경우 탐색은 최대 7회 비교로 끝납니다.
- 이번 실험: 정렬되지 않은 난수를 삽입해서 높이가 14가 되었습니다. 완전한 균형은 아니지만 최악보다는 훨씬 좋은 모양입니다.
- 한쪽으로 치우친 경우: 이미 정렬된 순서(오름차순/내림차순)로 삽입하면 트리가 연결 리스트처럼 한 줄이 됩니다. 높이가 100이 되어 탐색이 최대 100회, 생성 비용도 약 4,950회(1+2+...+99)까지 늘어나서 순차 탐색과 다를 바 없어지거나 더 나빠집니다.

즉 BST의 이점은 데이터가 무작위에 가깝게 들어와서 트리가 어느 정도 균형을 유지할 때 얻어지며, 균형을 보장하려면 AVL 트리나 레드-블랙 트리 같은 균형 이진 탐색 트리가 필요합니다.

## 5. 결론

- 탐색 성능만 보면 BST가 순차 탐색보다 약 10배 효율적이었습니다.
- 생성 비용을 포함해도 50회 탐색 기준으로 BST가 약 4배 유리했습니다.
- 다만 이 이점은 탐색 횟수가 충분히 많고 트리가 균형에 가까울 때 성립합니다.
